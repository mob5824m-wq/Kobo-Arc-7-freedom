KOBO ARC 7 FREEDOM · OPTICAL TRANSFER

Your file. Through the camera.

Actual file bytes travel across a repeating sequence of QR codes. No account, Wi-Fi connection, upload server or QR-reader service. Open this saved HTML file on the other computer or phone, or use QR Transfer → Receive (or Files → Receive QR bytes) on the Kobo.

Codes are not encrypted: anyone who can see them can copy the file. Keep devices awake. Up to 64 MiB per file (legacy mode: 1 MiB). At Standard density and normal speed, 1 MiB takes about 27 minutes for one clean pass; 64 MiB can take over a day. Missed frames add time. The Kobo app keeps receive progress on disk; this webpage keeps unsaved progress only while open. Use LAN sharing when speed matters.

02 / Receive bytes

Start the camera and scan the other device’s codes. Accept the file header, then keep scanning. Repeats and out-of-order frames are safe.

Save verified file

The full SHA-256 hash must match before Save appears. Nothing is opened or installed automatically. Browser downloads may rename duplicate filenames.

Camera does not open?

Allow this page to use the camera and close other camera apps. Browsers require HTTPS or localhost for camera access; opening a saved file directly works in some browsers but not all. Sending from a saved file works without camera access. For a completely offline setup, display codes here and receive them with the Kobo’s built-in Files camera. No BarcodeDetector API or external scanner app is required.

Offline use & compatibility

This file contains its QR encoder and decoder. It makes no network requests. New Arc7 byte-transfer protocol v2 supports 64 MiB and 128/512/1024-byte density profiles. This page and the Kobo app receive v1 and v2; select Legacy to send to an older 1 MiB companion. Generic QR-link readers cannot reassemble these bytes. The separately installable QR-Transfer.apk and Files on Android 4.0+ support both directions, including front-only cameras. Native receivers can resume after closing: reopen Saved receives or rescan the same header, and reselect the identical file/name/profile at the sender. Browser receiving requires enough memory for the whole file. Browser receiving needs a current browser with camera access, TextEncoder and Web Crypto. Leaving this page pauses the loop and camera; unsaved data remains only while the page is open.
